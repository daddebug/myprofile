## Owner permission vs. Editing Mode (verified 2026-09-12)

Owner permission (`useOwnerMode()`, `src/hooks/useOwnerMode.ts`) and editor-chrome visibility (`useEditingMode()`, `src/hooks/useEditingMode.ts`) are two independent states, never one flag reused for both:

- **Owner permission** answers "can this browser act as the owner" — gates draft/hidden/unpublished project click-through and owner-only routes. DEV defaults to owner=true; a real visitor or any production build is always `false` regardless of stored state or query params.
- **Editing Mode** answers "should editor chrome render right now" — gates `ProductionExportDock`'s contents, the Owner/Visitor Preview toggle, `InlineTemplateField`, homepage/other-projects slot pickers, `CaseStudyEditorDock`/"EDIT CONTENT", and the Project Archive (`/work`) and Game Experience (`/play`) management toolbars. Defaults to `false` even for the owner — a fresh local DEV open renders identically to the public site except for one small, fixed top-right pencil icon (`data-edit-mode-trigger` in `ProductionExportDock.tsx`), the only entry point that flips it on. Turning it off makes all of the above disappear immediately; owner permission (and therefore draft-project clickability) is unaffected.
- Every gate follows `if (isOwner && editingMode) show editor UI`, never `if (isOwner)` alone; project/slot click-permission checks use `isOwner` alone, never `editingMode`. `ProjectEndSections`'s "Other Projects" slot cards on project pages get the same `isOwner`/`isEditingUI` split as `HomePage`'s grid.
- `CaseStudyEditorDock` (`src/components/CaseStudyEditor.tsx`) keeps a literal `if (!import.meta.env.DEV || ...)` as the first condition specifically so its whole JSX (including the "EDIT CONTENT" button) is dead-code-eliminated from the production bundle, not just runtime-null — verified via `grep` on the built `dist/assets/*.js`: `data-edit-mode-trigger`, `data-production-export-dock`, and `data-owner-editor-dock` are all fully absent.
- Verified live on a real `pnpm dev` server (clean `localStorage`) and a real `vite preview` of `pnpm build`'s output, including forcing `?owner=1` and both storage keys to `"1"` against the production build: owner permission and editing-mode both stayed hard-`false`, and zero editor DOM rendered.
